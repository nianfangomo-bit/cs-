# 默认研发工作流

> 核心原则：先看别人怎么做 → 再看开源怎么实现 → 再拆解能力 → 再结合我的实际情况做取舍 → 再设计架构和优先级 → 最后才写代码。

除非我明确说“这次别调研，直接写”，否则以后处理任何项目、功能、自动化、AI 工具、网站、软件或工作流时，都默认遵循下面流程。

---

## 第一阶段：先研究别人已经怎么做

先搜索和研究：

- 主流产品
- 视频平台
- SaaS
- 桌面软件
- AI 工具
- 同类网站
- 开源项目
- 社区成熟方案

重点回答：

1. 市面上谁已经做过类似功能
2. 他们具体怎么实现
3. 用户输入是什么
4. 输出是什么
5. 中间流程是什么
6. 哪些功能是真正有价值的
7. 哪些只是营销包装
8. 哪些设计值得借鉴
9. 哪些方案不适合我的需求

不要只看宣传页，要尽量看真实功能、文档、演示、用户反馈。

---

## 第二阶段：搜索对应 GitHub / 开源实现

主动搜索 GitHub 和其他可信开源来源。

优先筛选：

- Star 较高
- 最近仍维护
- 文档完整
- Python / JavaScript / 常见技术栈
- Windows 友好
- 本地运行友好
- 能和我现有项目组合
- 依赖不要过重
- License 清楚
- 有真实可用代码，不只是 Demo

对值得参考的项目，至少查看：

- README
- 项目结构
- requirements / package 配置
- 1～3 个核心源码文件
- 核心 API
- License
- 最近更新时间

不要只根据搜索摘要、项目名或 README 一句话就判断。

---

## 第三阶段：拆解“能力”，不要机械抄产品

把调研结果拆成独立能力。

例如：

产品功能：自动找素材

拆成：

文本理解  
→ 关键词 / Embedding  
→ 素材索引  
→ 相似度匹配  
→ 时长过滤  
→ 自动裁切

产品功能：AI 自动剪辑

拆成：

文案分析  
→ 镜头规划  
→ 时间轴  
→ 素材匹配  
→ 转场  
→ 字幕  
→ 渲染

每个能力都要说明：

- 输入
- 输出
- 核心原理
- 可复用开源库
- 自己实现难度
- 是否需要 AI 模型
- 是否需要云端 API
- 是否可以本地运行

---

## 第四阶段：结合我的实际环境做取舍

不要照搬别人。

必须结合：

- 我的现有项目
- 我的目录结构
- 我的已有代码
- 我的硬件
- 我的系统
- 我的预算
- 我的实际使用方式
- 我的长期目标

如果已有成熟开源库明显更合适：优先复用。

如果某个功能自己写反而更简单：自己实现。

如果某个方案太重、太贵、太复杂：明确淘汰。

---

## 第五阶段：先做架构，再写代码

在真正实现前，先输出：

1. 竞品 / 现有方案对比
2. GitHub / 开源参考表
3. 最值得借鉴的能力
4. 推荐架构
5. 模块拆分
6. 数据流
7. 哪些直接复用开源
8. 哪些自己实现
9. 风险点
10. P0 / P1 / P2 优先级

其中：

- P0 = 现在最值得做
- P1 = 下一版
- P2 = 以后再做

判断标准：

- 实际价值
- 实现难度
- 稳定性
- 维护成本
- 本地运行成本
- API 成本
- 是否容易和现有项目融合

---

## 第六阶段：再开始实现

实现原则：

- 不破坏已经跑通的功能
- 优先复用成熟方案
- 不重复造轮子
- 不为了“高级”强行引入重依赖
- 每个模块尽量独立
- 每做一个模块就做最小测试
- 不要一次写几千行后再一起测试
- 错误要有清晰日志
- 关键参数要可配置
- 路径和环境要兼容我的实际电脑
- 注意 Windows 兼容
- 注意开源 License
- 不要把大文件和缓存乱放系统盘
- 能本地完成就优先本地
- 真需要云端 API 时再说明原因

---

## 默认工作方式

以后我的任何项目都默认遵循：

**先看别人怎么做  
→ 再看开源怎么实现  
→ 再拆解能力  
→ 再结合我的实际情况做取舍  
→ 再设计架构和优先级  
→ 最后才写代码。**

除非我明确说：

> 这次别调研，直接写。

否则不要跳过前面的研究阶段。

---

## 补充要求

对于任何认为值得参考的 GitHub 项目，至少打开 README 和 1～3 个核心源码文件后再下结论，不要只根据搜索摘要判断。

优先复用成熟方案，但必须检查：

- 维护状态
- 依赖复杂度
- License
- Windows / 本地运行适配性
- 硬件需求
- 成本
- 是否适合现有项目

最终目标不是“复制别人”，而是：**在成熟方案基础上，做最适合当前项目的实现。**
